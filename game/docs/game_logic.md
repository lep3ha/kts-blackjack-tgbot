# Game Logic

## Поддерживаемые действия

- `hit`
- `stand`
- `double`

Не поддерживаются:
- `split`
- `insurance`
- `surrender`

## Карты и подсчет очков

- формат карты: `<RANK><SUIT>`, например `10H`, `A♠️`, `7D`;
- `J/Q/K/10` дают 10 очков;
- `A` сначала считается как 1, затем повышается до 11, если это не ведет к bust;
- натуральный blackjack фиксируется при двух картах и сумме 21.

## Базовый ход раунда

1. Сессия создается в `lobby_open`.
2. `start` раздает по две карты каждому игроку и дилеру.
3. Выбирается первая playable позиция.
4. Игроки выполняют действия или timeout.
5. Когда playable hands заканчиваются, играет дилер.
6. Выполняется settlement, обновляются балансы, сессия закрывается.

## Семантика действий игрока

### `hit`

- игрок берет одну карту;
- если `projected_score < 21`, ход может остаться у того же игрока;
- при `21` или bust ход переходит дальше.

### `stand`

- игрок не берет карту;
- рука считается завершенной;
- ход переходит к следующей playable позиции или дилеру.

### `double`

- разрешен только на первых двух картах;
- требует достаточный банк для удвоенной ставки;
- ставка удваивается;
- игрок берет ровно одну карту;
- после этого рука всегда завершается без дополнительного выбора действий.

## Timeout и bot stop

### Timeout

- допустим только для текущего активного игрока;
- принимается только после истечения `current_timer`;
- трактуется как forced `stand`.

### `single_stop`

- работает как auto-stand активного single игрока;
- не shortcut-ит settlement по текущим картам;
- после stop сервис доигрывает дилера и закрывает сессию обычным путем.

### `group player stop`

- выводит конкретного active игрока из group раунда;
- remaining active players продолжают игру, если они есть.

## Правила дилера

- дилер добирает карты, пока его сумма `< 17`;
- на `17+` дилер останавливается;
- логика дилера выполняется автоматически как terminal phase после завершения игроков.

## Settlement

Для ставки `bet`:
1. natural blackjack игрока против не-blackjack дилера -> `delta = floor(1.5 * bet)`
2. bust игрока -> `delta = -bet`
3. bust дилера при живой руке игрока -> `delta = +bet`
4. score игрока выше score дилера -> `delta = +bet`
5. равенство -> `delta = 0`
6. иначе -> `delta = -bet`

Баланс обновляется в момент settlement в той же транзакции, что и финальное закрытие раунда.

## Важная runtime особенность

Публичные методы сервиса автоматически дренируют terminal phases. Поэтому клиент после `apply_action`, `handle_timeout` или bot-facing `single_stop` обычно получает уже финальный snapshot, если после действия ход игроков закончился.
