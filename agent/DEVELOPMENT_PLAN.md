# DEVELOPMENT_PLAN.md

Цель файла: единый рабочий шаблон для планирования багфиксов, исправления ошибок и развития функциональности.

## Статусы
- planned
- in_progress
- blocked
- review
- done

## Приоритеты
- P0: критичный баг/падение/потеря данных
- P1: функциональный дефект без потери данных
- P2: улучшение/рефакторинг/техдолг

## Правила ведения
- Один пункт = одна проверяемая задача.
- Для каждой задачи указывать критерий готовности.
- Перед началом реализации задача должна иметь план и список затрагиваемых файлов.
- После выполнения фиксировать, какие тесты запущены и результат.
